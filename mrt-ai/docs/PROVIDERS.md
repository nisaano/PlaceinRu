# Источники данных и доступ к API

Исследование официальных материалов: 2026-10-03. Регистрация, заявки партнёрам, получение ключей, подключение платных планов и реальные API-вызовы в этой задаче не выполнялись. Публичная документация не подтверждает доступ конкретному проекту. Перед подключением повторно проверить условия.

## Главный вывод

Безусловно бесплатный live-доступ ко всем авиабилетам, поездам, отелям и гидам для PlaceinRu не установлен. Разделять: бесплатные данные, бесплатную квоту API, партнёрский доступ после одобрения, коммерческий договор и собственный хостинг. Наличие документации и affiliate-программы не означает открытый API с гарантированными ценами.

Ссылки на сайт бронирования реализуемы отдельно от live-поиска. Поисковая ссылка не подтверждает существование конкретного тарифа. Полный вариант «в бюджете» нельзя обещать при неизвестных обязательных расходах.

## Кандидаты для интеграции

| Авиа: Aviasales / Travelpayouts | Data API использует кэш поисков; live search — отдельный доступ с требованиями к проекту [T1] | Кэш — только ориентир с актуальностью. Live-адаптер отключён до получения доступа. Возможность нулевой платы конкретному проекту не подтверждена |
| Отели: ETG Affiliate API | Предусмотрен affiliate-продукт и процедура выхода в production [H1, H2] | Рассматривать после согласования партнёрства, условий и права перехода на внешний checkout. Не обещать бесплатный production API |

| Карта: OSM raster tiles | Есть условия атрибуции, кэширования и запрет массовой предзагрузки; нет SLA [O2] | Только обычный просмотр в малом стенде при соблюдении политики; endpoint сменный, production-провайдер определяется отдельно |

Для первого каталога подготовить канонические ID/координаты; далее выбрать отдельный разрешённый сервис или self-hosted |
| Дорожная геометрия: OSRM | API route/table для геометрии и матриц [R1] | Исследовать локальный экземпляр для пилотной территории. Open-source не означает бесплатную инфраструктуру; public demo не считать production-зависимостью |
| Гиды/активности | По ТЗ список реальных партнёрских гидов приходит от Backend | Начать с согласованного ручного каталога и ссылок заявок. Открытый бесплатный API с нужным покрытием не подтверждён; отсутствие гида возвращать явно |

Для ресторанов и объектов официальная ссылка допустима только из проверенного источника; при неизвестной форме бронирования показывать «Открыть сайт», а не «Забронировать». Для гида ссылка inquiry означает заявку, а не гарантированную доступность. Не выводить синтетические ссылки fixtures как работающие предложения.

## Условия включения каждого адаптера

В реестре провайдера хранить: идентификатор, официальный URL документации и условий, дата проверки, разрешённый сценарий и коммерческое использование, основание доступа, тариф/квота, покрытие РФ, auth, rate limits, TTL, требования атрибуции, права хранения/повторного показа, допустимый способ формирования ссылок и ограничения изображений. Непроверенные значения отмечать `unconfirmed`; они не означают отсутствие ограничений.

Статусы адаптера: `research → access_pending → sandbox → verified → enabled`. `verified` требует успешного запроса, проверки нормализации и подтверждённых условий для проекта. Проверки sandbox не подтверждают реальное наличие.

Код адаптера: timeout, ограниченные retries/backoff, учёт квоты, отмена, circuit breaker, кэш только в разрешённых пределах, provenance, различение пустого результата/отказа/таймаута. Цена хранится с fingerprint поиска и сроком годности источника; единого произвольного TTL для всех услуг нет. Ключи — серверные env, исключены из логов и UI.

Использовать официальные API, разрешённые выгрузки и открытые лицензии. Не обходить авторизацию, лимиты или ограничения партнёра; публичная веб-страница сама по себе не разрешает массовый сбор. Не копировать отзывы и изображения без проверенного права использования.

## Режимы результата

- `fixture`: синтетические данные для разработки, баннер «демо», не использовать для утверждений о реальной поездке. Полностью воспроизводимые тесты без сети.
- `manual`: проверенные вручную справочные записи с датой и источником; не заявлять live-наличие.
- `cached`: ранее полученное предложение, обязательно время наблюдения; устаревший тариф нельзя использовать как подтверждённый.
- `live`: ответ источника на текущие параметры. Если источник не подтверждает наличие или цена неполная, соответствующие поля остаются unknown.

Если ключа нет: работа с fixtures или справочными объектами, возврат `partial` и объяснение недостающей категории. Если сервис упал: допустимый кэш с маркировкой или неполный результат. Не дорисовывать билеты/отели моделью. Автономное демо и реальный MVP — разные критерии готовности.
