# Дневник изменений mrt-ai

Хронологический журнал заметных изменений реализации. Тестовые данные и модельные оценки явно обозначаются; запись в журнале не означает, что запланированная функция уже готова.

## 2026-10-04

### Диагностика потери соединения с dev API

- При сетевой ошибке отправки формы или правки dev-чат теперь объясняет, что локальный API недоступен, и предлагает перезапустить `.\start.cmd`, затем открыть адрес из строки «Чат готов».
- В `README.md` добавлена инструкция восстановления. Проверены отображение сообщения в браузере, health endpoint, полный unittest suite (91 PASS) и экспорт 19 API-схем.

### Свободный текст: улучшение извлечения слотов

- `rules-v1` теперь распознаёт направление перед городом отправления («Москва из Казани», «Карелия из Санкт-Петербурга»), частые выражения состава группы («вчетвером», «парой», «четыре взрослых», «два путешественника») и календарный диапазон русскими словами («1 и 2 июля 2028 года»). Проверяются невозможные даты.
- После анализа первого held-out ошибки первоначальные test-семейства честно перенесены в validation; для новой версии создано пять ранее не использованных групп формулировок в test. Датасет v2: 63 synthetic примера, 15/33/15 train/validation/test.
- Текущий fresh synthetic holdout: 15/15 полных slot exact matches. Это маленькая искусственная проверка текущих правил, а не обученная ML-модель и не оценка реального качества.
- Следующим ML-этапом остаётся сбор разрешённых и обезличенных сообщений, затем обучение и сравнение slot extractor с детерминированным baseline; сейчас inference слотов всё ещё выполняет `rules-v1`.

### Структурированная форма маршрута в dev-чате

- Браузерный dev-чат переведён на form-first сценарий: свободное поле выключено до отправки начальных требований формой; после этого текстовое поле используется для правок собранной поездки.
- Форма по концепту включает календарную дату начала, длительность, origin/destination с режимом подбора, состав группы 1–4, детей, категории интересов, гида и бюджет с явными basis/period.
- Отправка сохраняет нормализованные поля `TripRequest` через существующий session API; пустые необязательные значения явно сбрасываются. В интерфейсе можно раскрыть точный JSON `updates`, отправленный API.
- `Edit` получил необязательный user-facing `message`, чтобы структурная форма сохраняла в истории понятный запрос, не меняя поведение существующих клиентов.
- Форма не изображает NLP-извлечение: структурные значения поступают напрямую, а свободный текст тестируется отдельно через rules-v1/RuBERT. Реальный каталог по-прежнему ограничен имеющимися fixture регионами.
- Полный набор после изменений: 87 unit/API tests PASS; syntax check inline JavaScript PASS.

### Benchmark извлечения параметров поездки

- Первоначальная версия содержала 48 полных/частичных пользовательских фраз, разметку восьми нормализованных полей и family-separated train/validation/test (15/15/18).
- Добавлены проверка схемы/отсутствия leakage и evaluator, который прогоняет `rules-v1` через тот же trip reducer, считает per-slot accuracy и exact match, показывает ошибки test split.
- Первоначальный test из 18 фраз выявил проблемы с неявным направлением, `вчетвером`/`парой` и текстовыми датами. После просмотра результатов эта версия больше не считается независимым holdout: её test families перемещены в validation версии v2 и доработана система разметки.
- Dev-чат показывает нормализованное текущее состояние слотов (отправление, направление, даты, длительность, размер группы, дети и интересы), чтобы разработчик видел не только текст ответа, но и параметры, собранные parser-ом.
- Следующий шаг — собрать разрешённые обезличенные пользовательские примеры и разметить их, прежде чем выбирать/дообучать ML slot extractor. Числа, даты и boolean-подтверждения по-прежнему требуют точной нормализации и валидации.

### Multi-label intent classifier: синтетический обучающий пилот

- Добавлены taxonomy из 9 intents, reproducible corpus builder и `data/datasets/intent-v1.json`: 135 синтетических вручную составленных примеров, 81/27/27 train/validation/test, разделение целыми семействами перефразировок.
- Загружен закреплённый MIT encoder `cointegrated/rubert-tiny2` с проверкой SHA-256. Реализованы MRT-AI multi-label fine-tuning, выбор порога на validation, checkpoint manifest, inference adapter и сравнение с `rules-v1`.
- Последний synthetic test: RuBERT macro/micro F1 0.6266/0.6885, exact match 0.2963; rules-v1 — 0.7797/0.7937 и 0.7037. Это крошечный синтетический smoke-test, не оценка реального качества; classifier не управляет ответом или состоянием поездки, правила остаются parser Миши.
- Локальный browser dev-чат обновлён для проверки произвольных сообщений: показывает ответ rules-v1, classifier intents, порог и уверенность по всем классам. Сравнительный endpoint включён только в `scripts.dev`, модель загружается лениво. Недоступность checkpoint/dependencies показана явно, не мешает rules-v1 диалогу.
- Повторяемые команды и ограничения задокументированы в `docs/EVALUATION.md` и `docs/ML_STRUCTURE.md`. Следующее необходимое действие — собрать обезличенные ручные labels и расширить независимый holdout.

### Структура MRT-AI, роли моделей и cleanup

- Разделён код: `app/` — API/диалог Миши; `mrt_ai/contracts/` — общие доменные контракты; `mrt_ai/retrieval/` — собственная логика pipeline, BM25 baseline и отдельный SBERT adapter. `MrtAiRetrievalPipeline` централизует выбор поисковой стратегии; поведение BM25 default и semantic option сохраняется.
- SBERT веса перемещены из общего cache каталога в `models/embeddings/sbert_large_nlu_ru/`, Git-ignored. API и evaluator используют новый путь. UI/API брендированы как `mrt-ai · Миша`; PlaceinRu остаётся названием продукта.
- Проверены карточки Hugging Face: SBERT `ai-forever/sbert_large_nlu_ru` — MIT (бесплатный локальный encoder), RuBERT-tiny2 `cointegrated/rubert-tiny2` — MIT. Закреплён выбор RuBERT-tiny2 как внешней основы будущего intent classifier. Сам MRT-AI будет владеть intent labels, обучаемой головой и pipeline; классификатор не объявляется реализованным до появления размеченного набора и проверки.
- Удалена дублирующая консоль `scripts/dev_chat.py`; браузерный чат Миши остаётся единственным dev UI. `tests/test_dev.py` теперь проверяет browser launcher и API без консольного интерфейса. Исходные CSV, docs, fixtures и `data/runtime/sessions.sqlite3` сохранены.
- Добавлена карта структуры и ролей моделей в `docs/ML_STRUCTURE.md`; сокращён PROJECT_CONTEXT. Полный набор после рефакторинга: 78 unit/API тестов PASS. SBERT метрики не изменились; на отдельном прогоне после перемещения средняя latency была 62.0 ms (p50 61.5, p95 69.9), warmup 7.05 s; время зависит от нагрузки CPU/кэша.
- Удалены только сгенерированные `.test-tmp` и пустые `artifacts/`, `dev-ui/`. Исходные CSV, fixtures, docs и сохранённая база `data/runtime/sessions.sqlite3` не тронуты.

### Локальный SBERT embedding retrieval

- Добавлен опциональный `ranking_method: "embedding"` в `POST /v1/search/places`; BM25 остаётся default и не требует ML runtime. Для embedding используется `ai-forever/sbert_large_nlu_ru`, закреплённый commit revision `89deeaa197d9d146e5763ac1f5fe32bf66817126`, CPU inference и masked mean pooling с нормализацией векторов.
- Добавлены optional `requirements-ml.txt` и `scripts.download_embedding_model`. Скачиваются только нужные tokenizer/config файлы и `model.safetensors` (1,707,679,808 bytes); SHA-256 проверяется до записи локального model manifest. Модель хранится в игнорируемой Git-папке `models/`; API ничего не загружает из сети. Если model/dependencies отсутствуют, запрос получает явную ошибку 503, без незаметного BM25 fallback.
- Добавлен lazy loader, небольшие inference batches, ограниченный cache эмбеддингов synthetic candidates и сравнение BM25/embedding в `scripts.evaluate_retrieval`; embedding отчёт включает NDCG@5, Recall@5, MRR и CPU latency после model warmup. Полный набор: 77 unit/API тестов PASS, включая стабильную сортировку/кэш, schema и явную недоступность модели.
- Ресурсы машины: CPU-only PyTorch установлен в `mrt-ai`; на D: свободно около 323.6 GB, установленная RAM — около 15.7 GB. Закреплённый snapshot проверен по SHA-256; действительный embedding маршрут API проверен локальным запросом.
- Первый корректный прогон на 8 synthetic queries: SBERT NDCG@5=0.8577, Recall@5=0.8542, MRR=1.0000; BM25 NDCG@5=0.9031, Recall@5=0.8958, MRR=1.0000. SBERT в этом крошечном наборе уступил лексическому baseline, поэтому BM25 остаётся default. После warmup CPU latency embedding query: mean 240.7 ms, p50 228.8 ms, p95 284.3 ms; подготовка модели и candidate vectors заняла 22.25 s. Это только локальная техническая оценка.
- Все catalog candidates и judgments остаются synthetic. Эти smoke-метрики не являются внешней оценкой; модель не обучалась и не строит проверенные маршруты.

### Локальный поиск по объектам: BM25 baseline

- Добавлен endpoint `POST /v1/search/places` для поиска по объектам выбранного региона. Нужен явный `data_mode: fixture`; выдача содержит только записи с synthetic provenance.
- Реализован воспроизводимый лексический ранжировщик BM25 (`bm25-lexical-v1`) с полями названия, тегов и описания; в ответ включены score и совпавшие нормализованные термины. Это baseline, не embedding-модель.
- Добавлен небольшой вручную размеченный синтетический набор `data/fixtures/search-relevance.json` и evaluator `python -m scripts.evaluate_retrieval`, считающий NDCG@5, Recall@5 и MRR.
- Последний локальный прогон baseline: 8 smoke-запросов, mean NDCG@5 = 0.9031, mean Recall@5 = 0.8958, MRR = 1.0000. Метрики измерены на синтетических запросах о синтетических объектах, созданных в одном проекте; это регрессионная проверка, не независимая оценка и не доказательство качества на пользовательских запросах.
- Ограничения: нет семантического сопоставления перефразировок без общих слов, модели/эмбеддингов, реальных POI, географической сортировки, маршрутизации, проверки расписаний, цен или доступности.

### Подготовка предыдущего ML эксперимента

- Рассмотрен [ai-forever/sbert_large_nlu_ru](https://huggingface.co/ai-forever/sbert_large_nlu_ru): официальный model card описывает русскоязычные sentence embeddings и mean pooling; Hugging Face metadata указывает MIT и 426,908,672 параметра. Модель тяжёлая для CPU. Рассмотрен также [sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2): multilingual embedding model, 384 dimensions и Apache-2.0 по model metadata. Качество на PlaceinRu не измерялось.
- Выбрана SBERT модель, но до реализации настоящего encoder и закрепления snapshot её векторы ещё не вычислялись; runtime зависимости присутствовали в project venv. Теперь следующий самостоятельный шаг — отделённый, более крупный русскоязычный evaluation набор и данные для intent classification.
