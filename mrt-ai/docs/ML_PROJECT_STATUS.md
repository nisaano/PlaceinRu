# Статус ML/AI проекта PlaceinRu

Обновлено: 2026-10-06.

## Текущий этап

Демо этапа: форма → параметры TripRequest → рекомендации/выбор пилотного региона → явный fixture-каталог → BM25 ranking → provisional план по дням. Это работает для проверки алгоритма на Москве/Московской области. Текущая версия ранкера — `trip-fit-bm25-v3`; для неё заведены development-набор и holdout на синтетических данных.

## Завершено

- Разделены API/диалог Миши (`app/`) и локальный pipeline (`mrt_ai/`). Пользовательский frontend находится вне области mrt-ai; есть только минимальный dev чат.
- Pydantic контракты TripRequest, Candidate/Offer/Search, ranking и RouteProposal; версии JSON-схем экспортируются.
- Сессии и сообщения сохраняются локально; слоты можно уточнять через `rules-v1` и структурированную форму.
- Есть карточки двух регионов, ручной/fixture/cached provider с разделением режимов и 17 синтетических объектов в fixture каталоге.
- BM25 — retrieval baseline. SBERT доступен как необязательный локальный retrieval encoder; по текущему маленькому синтетическому набору уступил BM25.
- Есть synthetic intent classifier и slot benchmark. Они полезны для инженерного цикла, но не доказывают качество на реальном трафике; rules-v1 остаётся основным parser.
- Есть явный `/v1/rank`, объяснимые компоненты и фильтр запрещённых интересов. `trip-fit-bm25-v3` разделяет прямое совпадение интереса и частичную тематическую близость; последняя не считается `matched_interest`. Исключения фильтруются по прямому совпадению. API сообщает факторы, которые нельзя оценить по текущим данным.
- Есть `/v1/route/proposal`: раздаёт уникальные рекомендованные объекты по дням на fixture/cache. Статус provisional; проверенные переезды, реальные времена и полный бюджет отсутствуют.
- Есть read-only Java trips adapter; это не каталог мест и не проверенная production-интеграция.

## Частично завершено / отсутствует

- Обученная slot extraction и intent-модель, пригодная для production: нет. Эксперимент RuBERT intent слабее правил и не управляет диалогом.
- Preference profile с версиями, весами, provenance и явным/предполагаемым предпочтением: нет отдельной модели; сейчас есть списки слотов и эвристики ranking.
- Реальные конкретные объекты: локальный CC0 snapshot Wikidata содержит 2 593 места для Москвы и Московской области и доступен cached-провайдеру. OSM snapshot отдельно не создан из-за HTTP 504/read timeout; не повторять массовые запросы к публичным endpoint’ам.
- Цены/доступность отелей, билетов, активностей и гидов, booking links: нет подтверждённых источников или live-интеграций.
- Ranker v3: development-набор из 12 вручную размеченных сценариев дал NDCG@5 0.9742 / Recall@5 0.9722. Отдельный holdout `trip-fit-holdout-v1` (6 авторских synthetic запросов) дал NDCG@5 0.9915 / Recall@5 1.0; музейный сценарий ранжирует галерею и музейное пространство выше гастрономической прогулки. Это не независимое человеческое исследование и не production evidence. Multi-interest development-кейс: 4 из 6 объектов в top-5, все 6 в полном списке. Даты/сезон, бюджет, вместимость группы и транспорт остаются `unscored_factors`.
- Planner: нет матрицы времени, реальной оптимизации очередности, проверки расписаний, бюджета и полного hotel/transport plan. Время перемещения не выдумывается.
- Свободные LLM-объяснения, ChangeSet для редактирования мест, production авторизация/сохранение маршрута и end-to-end JWT интеграция: нет.

## Данные и модели

- `data/datasets/intent-v1.json`: 135 synthetic multi-label примеров, 9 labels, split 81/27/27 по семействам.
- `data/datasets/trip-slots-v1.json`: 63 synthetic фразы, 8 слотов, split 15/33/15. 15/15 exact match у rules-v1 на маленьком искусственном test нельзя переносить на пользователей.
- `data/fixtures/search-relevance.json`: 8 synthetic retrieval queries; прежние NDCG@5 BM25 0.9031, SBERT 0.8577.
- `data/fixtures/trip-fit-relevance-v1.json`: 12 вручную размеченных synthetic TripRequest-сценариев и один диагностический unknown-interest кейс. Запуск: `.\venv\Scripts\python.exe -B -m scripts.evaluate_trip_fit`. Это не независимая разметка или production benchmark.
- `data/fixtures/trip-fit-holdout-v1.json`: 6 заранее размеченных synthetic запросов для отдельной проверки. Запуск: `.\venv\Scripts\python.exe -B -m scripts.evaluate_trip_fit --dataset data/fixtures/trip-fit-holdout-v1.json`. Разметка авторская, поэтому результаты остаются smoke checks.
- Модельные веса хранятся локально в игнорируемом `models/`; не коммитить веса и не читать `.env`.

## Проверки

Development evaluator: 13 cases (12 metrics + 1 diagnostic), NDCG@5 0.9742, Recall@5 0.9722. Holdout evaluator: 6 cases, NDCG@5 0.9915, Recall@5 1.0. Оба набора synthetic и авторские. Проверены unknown-interest warning и относительный порядок музейных объектов. Полная регрессия после обновления каталога: 107 тестов PASS.

Сгенерирован blind-review worksheet на 6 сценариев (8–9 карточек на запрос) без model score, rank и object ID. Файл: `artifacts/trip-fit-review-v1.json`; answer key отделён в `artifacts/trip-fit-review-v1.answer-key.json` и не должен передаваться рецензенту. Порядок карточек перемешан с seed `20261006`. Создание и smoke-import формы проверены на 54 временных метках; реальных оценок ещё нет.

OSM snapshot не создан: основной Overpass endpoint ответил HTTP 504, оба fallback endpoint завершились timeout. Реальные места уже доступны из локального Wikidata snapshot. Не повторять массовые запросы к Overpass до снижения нагрузки/смены разрешённого источника.

## Следующая конкретная задача

1. Получить оценки от рецензентов в blind worksheet; сравнить согласованность оценок до пересчёта метрик. Пока worksheet использует synthetic-карточки, он проверяет только понятность relevance критериев.
2. Проверить v3 на реальных пользовательских сценариях с текущим Wikidata-каталогом; вручную проверить географическую точность, дубликаты и полезность карточек, затем расширять каталог дополнительными лицензированными источниками.
3. Не менять веса без внешней разметки; сезон, бюджет, вместимость и транспорт учитывать только после появления подтверждённых полей источника.

До независимой проверки не утверждать, что v3 улучшил пользовательское качество: разница в синтетических метриках — только development signal. Не подключать SBERT к ranking только потому, что он доступен для retrieval.

## Актуализация на 2026-10-06: реальные места

Создан `data/normalized/wikidata-places.json`: 2 593 координатных объекта — 1 219 в Москве и 1 374 в Московской области. Импортёр `scripts/import_wikidata_places.py` использует административную иерархию Wikidata `P131+` и публичный QLever endpoint; записи сохраняют QID, координаты, источник, CC0 и хеши. В cached-режиме API снимок читается локально. OSM Overpass по-прежнему недоступен, поэтому OSM snapshot отдельно не создан.

Проверено через API: `/v1/candidates/query` для области вернул 1 374 места, `/v1/search/places` нашёл 5 результатов по музейному запросу, `/v1/route/proposal` сформировал предварительный двухдневный черновик с 4 объектами. Новый importer и сохранённый snapshot покрыты проверками в `tests/test_wikidata_import.py`.

Эти места подходят для развития поиска и ранжирования, но ещё не подтверждают часы работы, актуальность, цену, рейтинг, безопасность, транспорт или возможность посещения. Координаты и категории сообщены участниками Wikidata; bbox только отсекает явные выбросы. Подробные условия и следующий шаг — в `docs/PLACE_DATASETS.md`.
