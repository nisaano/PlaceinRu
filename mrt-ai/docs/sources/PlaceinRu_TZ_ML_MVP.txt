PlaceinRu — Техническое задание для ML
Роль: ML-разработчик  |  MVP PlaceinRu  |  Версия 1.0

1. Цель
Разработать AI/ML часть PlaceinRu — систему, которая понимает естественный язык пользователя, извлекает параметры поездки, определяет намерение, находит недостающие параметры, рекомендует варианты и помогает перестраивать маршрут.
2. Главный принцип
ML отвечает за интеллект: NLP, intent, entity extraction, рекомендации, ranking и предпочтения маршрута.
ML не придумывает реальные цены, наличие билетов, наличие номеров, расписания, адреса или рейтинги. Эти данные передаёт Backend.
Критические результаты возвращать структурированным JSON, а не только свободным текстом.
3. Pipeline
User message → NLP/Intent/Entity extraction → TripRequest → Backend передаёт реальные candidates → filtering/ranking → рекомендации/изменения → Backend/Route Engine проверяет фактическую реализуемость.
4. Извлечение параметров
Минимум понимать: откуда, куда, даты/длительность, бюджет, количество взрослых, дети, активности, вид туризма, транспорт, нужен ли гид и какой гид.
Пример: «Хочу из Москвы в Сочи на 5 дней, бюджет 80 тысяч, нас двое, любим море и горы, едем на машине».
5. Intent
Минимальные intent: CREATE_TRIP, ANSWER_QUESTION, CHANGE_TRIP, CHANGE_DATE, CHANGE_TRANSPORT, CHANGE_HOTEL, CHANGE_ATTRACTION, CHANGE_RESTAURANT, ADD_ATTRACTION, REMOVE_ATTRACTION, ADD_GUIDE, REMOVE_GUIDE, CHANGE_BUDGET, REBUILD_ROUTE, SAVE_TRIP, ASK_ABOUT_TRIP.
6. Missing Parameters
После каждого сообщения определить, что уже известно и чего не хватает.
Не задавать повторные вопросы.
Если критичного параметра нет — задать короткий уточняющий вопрос.
Критичные параметры для генерации: откуда, куда, даты/длительность, бюджет, состав группы, предпочтения/активности и транспорт.
7. Recommendation Engine
Backend передаёт список реальных кандидатов: места, отели, рестораны, транспорт, гиды.
ML должен отфильтровать неподходящее и вернуть ранжированный список.
Рейтинг должен учитывать минимум: совпадение интересов, сезон, бюджет, локацию, транспорт, состав группы и популярность.
8. Embeddings
Подготовить embeddings для туристических объектов с использованием описаний, тегов, категорий и сезонности.
В проектном документе предусмотрено PostgreSQL + pgvector; конкретную embedding-модель и размерность нужно выбрать после короткого технического исследования.
Подготовить возможность переиндексации объектов.
9. Route Optimization
ML может предлагать состав и порядок объектов по дням.
Вход: объекты + координаты + длительность + часы работы + даты + транспорт + бюджет.
Выход: структурированная рекомендация по дням.
Фактические расстояния, время, часы работы и доступность проверяет Backend/Route Engine.
10. Бюджет
ML должен уметь выбирать более дешёвые альтернативы, если текущий вариант превышает заданный бюджет.
Принцип: budget <= X, если это жёсткое ограничение.
Фактическую стоимость и итоговый total считает Backend.
11. Автомобиль
При выборе автомобиля учитывать результаты Backend: distance, duration, fuel_cost, tolls.
Не придумывать стоимость топлива или платных дорог.
12. Гиды
Backend передаёт список партнёрских гидов.
ML ранжирует по региону, датам, специализации, типу туризма, интересам и бюджету.
Доступность и факт существования гида подтверждает Backend.
13. Изменения через чат
«Поменяй отель» → CHANGE_HOTEL + текущий item_id.
«Вылет хочу вечером» → CHANGE_DATE/CHANGE_TRANSPORT + новое ограничение.
«Убери экскурсию второго дня, добавь активность и не увеличивай бюджет» → REMOVE + ADD + budget constraint.
Нужно уметь описывать изменения структурированно.
14. Контракт ML API
Минимальные операции: parse, classify-intent, recommend, rank, optimize-route, recommend-guide.
Можно объединить операции в orchestration endpoint, если это упрощает архитектуру.
Пример ответа: { intent: 'CHANGE_HOTEL', entities: { destination: 'Сочи', budget: 100000 }, changes: { hotel: { action: 'replace', current_id: 123 } } }.
15. Собственная модель
Стратегическая цель — постепенно создать собственную ML-систему PlaceinRu.
В проектном документе указаны NLP, ruBERT/PyTorch, embeddings, контентная/коллаборативная фильтрация, геопространственная модель и pgvector/Faiss.
Для MVP не нужно пытаться сразу сделать всю конечную систему. Нужен рабочий минимальный pipeline, который можно улучшать без переписывания Backend.
16. Dataset
Подготовить структуру датасетов: text → intent; text → entities; user_preferences + object → relevance; trip_request + candidates → route/quality.
Собрать тестовый набор реальных русскоязычных пользовательских запросов и edge cases.
17. Feedback
Нужны события от Backend: recommendation_shown, clicked, saved, removed, hotel_selected/rejected, attraction_selected/rejected, restaurant_selected, guide_selected, route_edited, route_rebuilt, like/dislike.
Система должна позволять использовать эти данные для последующего улучшения рекомендаций.
18. Метрики
NLP: Intent accuracy/F1, Entity extraction Precision/Recall/F1.
Recommendation: Precision@K, Recall@K, CTR, saves.
Route: соблюдение бюджета, количество временных конфликтов, количество ручных изменений.
19. Что ML НЕ делает
Не является базой пользователей.
Не управляет авторизацией.
Не является источником истины по ценам/наличию/расписаниям.
Не сохраняет маршрут как единственный источник истины.
Не отдаёт критические решения только свободным текстом.
20. Definition of Done
Пользовательский запрос превращается в структурированный TripRequest.
Основные intent определяются.
Недостающие параметры определяются.
Backend ↔ ML контракт зафиксирован.
Реализован базовый ranking кандидатов.
Есть embeddings/семантический поиск.
Поддерживаются изменения маршрута через intent + structured changes.
Есть тестовый набор запросов и метрики.
Нет зависимости от выдуманных данных.
21. Что сделать первым
1) Совместно с Backend зафиксировать JSON Schema.
2) Сформировать список intent и entities.
3) Сделать parser/NER + intent baseline.
4) Подготовить тестовый датасет.
5) Сделать базовый recommendation/ranking pipeline.
6) Подготовить embeddings/поиск.
7) Сделать structured changes для редактирования маршрута.
8) Подключить ML к generation pipeline Backend.
9) Добавить evaluation и feedback.
